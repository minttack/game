## Critical original finding
On the inspected IRL branch, \`DefaultInput.ini\` had \`DefaultTouchInterface=None\`. The IRL player controller already attempted to create a \`MobileControlsWidgetClass\`, but the class was optional and had no fallback. \`AIRLCharacter\` already contains working input APIs \`DoMove\`, \`DoLook\`, \`DoJumpStart\`, \`DoJumpEnd\`, but whether the binary \`IMC_Default.uasset\` actually binds virtual joystick Gamepad axes **has not been inspected/verified in UE**. Mobile support therefore could not be assumed. \`DefaultGame.ini\` still called this "Third Person Game Template."

## Implemented on this feature branch
- Mobile virtual joystick source config: \`/Engine/MobileResources/HUD/DefaultVirtualJoysticks.DefaultVirtualJoysticks\` (Epic's standard dual touch joystick resource). Left stick is *intended* for movement, right for camera look. It depends on mapping contexts in the actual IRL Blueprint/Enhanced Input assets, which require UE editor inspection and on-phone validation.
- Native UMG \`UIRLMobileTouchHUD\` subclass, created using a WidgetTree/Canvas with self-hit-test-invisible root so native joysticks aren't intercepted. Adds visible **JUMP** button (hold press/release) and **EXPERIENCE** button (calls existing \`AIRLPlayerController::AdvanceIRLExperience\`; all original BIE gameplay guards still apply). No bespoke \`.uasset\` required for this native fallback. Creator-specified Blueprint class is preserved when assigned. Overlay only spawns on a local player controller when touch input is active.
- \`DefaultEngine.ini\`: Android **arm64**, target **SDK 35**, min SDK 26, landscape, package \`com.bieexperience.irl\`, **Development-only first APK**. GL ES 3.2 prioritized as a compatibility baseline (Vulkan off initially); use existing mobile scalable profiles and instrumented visual-quality controller from graphics branch. Android physical compatibility is unknown until on-device test. This is **not** a Play Store release/signing configuration. \`DefaultGame.ini\` now names the project IRL.
- \`irl_android_apk_runner.py\` and \`IRL_BUILD_ANDROID_APK_WINDOWS.bat\` run actual Unreal Engine 5.8 \`RunUAT.bat BuildCookRun -platform=Android -cookflavor=ASTC -clientconfig=Development -build -cook -stage -pak -package -archive\` for the **existing playable ThirdPerson map** (\`/Game/ThirdPerson/Lvl_ThirdPerson\`). The isolated Unreal-generated forest \`.umap\` remains a separate **UNVERIFIED** source art pipeline: it is not secretly cooked until a binary map exists and passes engine tests. Uses unique per-run archive, logs exit, refuses stale/missing or multiple APK candidates and checks CRC, Android manifest, DEX, arm64 .so and SHA-256 before reporting \`APK_FILE_VERIFIED_NOT_DEVICE_TESTED\`. Never installs or publishes automatically.
- Source-level tests \`test_android_mobile_contract.py\` plus 10 fake UAT process tests \`test_android_apk_runner.py\` verify missing/wrong SDK config, UMG touch fallback and actual-output evidence safeguards. These **do not** prove C++/UHT build, valid Android runtime or APK generated by Unreal.
- CI workflow updated to cover Android build-source changes and the new native contract tests.
